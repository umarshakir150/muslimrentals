## Summary

Confirmed the backend contract per Designer's analysis: Listing.bedrooms is Float (min 0, max 20) and Listing.bathrooms is Int (min 0, max 20) in both prisma/schema.prisma and the listings.ts Zod create/update schema — these bounds already match what the new numeric-input UI needs, so no schema/migration or bound change was required. To make this contract testable without a live database (Prisma client construction can fail at import time without DATABASE_URL, and there's no DB in this sandbox), extracted the previously inline listingCreateSchema/listingUpdateSchema/listingQuerySchema/reportSchema and the bedrooms/bathrooms/price range-filter logic out of src/routes/listings.ts into a new src/validation/listingSchemas.ts module (byte-for-byte behavior-preserving move — routes/listings.ts now imports from it instead of defining inline), and factored the filter-building code into a small pure function applyRangeFilters(where, q) used identically by GET /listings. Added Vitest (not previously configured in rentals/backend) with a vitest.config.ts and a comprehensive tests/validation/listingSchemas.test.ts covering: bedrooms boundary cases (0/studio, 20 ceiling, negative, 500-absurd, non-integer decimal allowed since the column is Float, non-numeric, missing), bathrooms boundary cases (0, 20 ceiling, negative, 500, half-bath rejection since column is Int, non-numeric), listingUpdateSchema partial-validation behavior, listingQuerySchema coercion/bounds for minBeds/maxBeds/minBaths/maxBaths, and filter-correctness unit tests for applyRangeFilters (gte/lte construction, combined bed+bath filters, the 0-value != null vs truthiness regression guard, non-mutation, and preservation of unrelated where-clause fields). Noticed the task description's claim that 'Vitest is set up in both rentals/backend and rentals/frontend' was not actually true on this branch (a separate in-flight, not-yet-merged task on another branch has similar backend test infra, but it hasn't landed on main) — set it up fresh here rather than assuming it existed.
