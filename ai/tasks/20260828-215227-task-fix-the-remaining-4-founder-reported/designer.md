## Recommendation

Approve items 2 and 4's planned fixes with two adjustments: (1) for item 4, do NOT add a global Escape-to-close handler to PostListingModal — leave it unbound (it isn't bound today) so nested autocomplete Escape-dismissal can't be hijacked into closing the whole form and re-losing data; close only via X/Cancel as the brief specifies. (2) for item 2, brighten `.rental-marker`'s background from #0a5c42 to a more unambiguously green, still-legible tone (roughly #16-#18 8a-92 4c-4e range) — one CSS value, no size/touch-target/clustering change, since both price pins and cluster-count bubbles share the class. For item 1, regardless of what QA's live-build check finds, have Frontend add a defensive CSS cap on Leaflet's control-pane z-index (currently defaults to 1000, above every app modal's z-[100]/z-[110]) so a stray map chrome element can never visually outrank a modal even in an edge case the local Playwright pass didn't hit — this is a low-cost, in-scope (lifecycle/stacking, not clustering) hardening step worth doing even if the stale-build theory turns out to fully explain the original report. No item here touches money, payments, or legal copy, so no founder/Legal sign-off is required before Frontend implements.
